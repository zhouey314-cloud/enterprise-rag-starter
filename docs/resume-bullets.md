# Enterprise RAG Starter — 项目贡献与简历素材

按合作问题或岗位选取两三条贡献，不把同一项目拆成多项成果。下面描述的是公开源码中的本地参考实现；网页演示、本地服务和模型质量的证据分别列出。

## 可以承担的实现

- 用 Python、SQLite / FTS5 和静态 JavaScript 实现可追溯资料查询。公开网页提供合成资料的词法检索与原文摘录；本地 CLI / HTTP 服务另行提供 MD/PDF/DOCX 入库、身份管理和来源查询。
- 将 token 解析为服务端保存的租户/角色，在检索前过滤访问范围，并在来源读取时再次检查权限、当前版本和生效期。记录来源文件哈希、版本及 Markdown 行、PDF 页、DOCX 段落位置；不把公开网页的 scope 选择器当作身份鉴权。
- 修复返回无关首句、标题含词但正文无证据，以及仅提到电话/邮箱却没有实际值的误答。保留相关检索线索和拒答原因，维护 Python / JavaScript 共用的摘录回归。
- 增加 SQLite 在线备份、独立路径恢复和只读健康检查，覆盖 WAL 中已提交数据、身份撤销状态、目标覆盖拒绝与失败清理。交付运行命令、可信操作员边界和恢复说明。

实现与运行入口：[权限/存储设计](adr-local-rag.md) · [新环境 QuickStart](local-quickstart.md) · [备份、恢复与缺值处理](OPERATIONS.md) · [完整案例](case-study.md)。

## 可直接采用的贡献表述

> 实现支持文档版本、权限过滤和来源定位的本地检索服务；将资料入库、CLI / HTTP 查询、证据不足拒答与备份恢复连成可复现流程，并保留失败回归及运行交接说明。

若需要更具体，可再补一条：

> 修复词法摘录在后续句、误导标题及缺少实际电话/邮箱值时的错误回答，使用共享回归检查 Python 与浏览器实现的一致性；保留既有语义改写漏检，不以机械检查代替真实语义质量。

## 合作与验收边界

适合先用自有或已授权、可核查的资料，验证入库、版本更新、来源查询、权限拒绝和恢复步骤，再确定下一阶段集成范围。交接可包含本地服务、元数据/权限约定、固定回归和恢复命令；这不代表已有客户投产或业务收益。

所有公开候选仍为 `synthetic_unverified`。词法覆盖不是语义蕴含；可选本地 embedding / hybrid 检索有单独依赖和评测，10-30 的工程修复没有重新验证其模型质量。生成模型未配置，生成质量 `NOT_RUN`；真实企业资料、生产 IAM / 部署与业务效果仍需独立验收。
