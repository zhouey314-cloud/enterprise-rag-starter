# 企业 RAG Starter — 面试讲述卡

## 60 秒

这个自建项目关注三个问题：答案能否追溯来源、查询是否遵守权限、证据不足时能否拒答。我把它分成三条路径：公开静态词法网页、可选本地 embedding 语义/混合检索、独立本地文件身份库。本地库支持 MD/PDF/DOCX、token 对应的租户/角色、版本与生效/过期/删除/冲突处理，以及 CLI 和 loopback HTTP。它不等于生产 IAM，网页也没有这些服务能力。本次修复了“检索到正确文档却固定摘第一句”的问题，Python 和浏览器共享十条反例由 2/10 提升到 10/10。所有素材仍是 synthetic_unverified；本地 60 条必需词法案例通过，两条语义改写失败，不能说成企业准确率。

## 3 分钟演示顺序

1. 在公开网页展示支持时段、证据不足拒答、public/team 的演示过滤；解释这不是身份认证。
2. 展示 [本地 quickstart](local-quickstart.md) 的入库、身份查询与来源定位，说明过期、删除、跨租户和冲突的保守拒答。
3. 对照 [失败分析](../FAILURE_ANALYSIS.md)：标题/整块文本曾让无关首句通过；现在仅给实际返回的句子评分，标题只用于检索。时钟范围是词法提示，不能证明语义蕴含。
4. 展示测试与评测证据，然后说明真实模型、真实政策和生产验收未完成的边界。

## 技术追问

- **架构取舍？** 静态可检查演示、本地可选模型、本地身份文件库分开；不把浏览器 scope 说成生产 ACL，也不把本地能力说成线上已部署。
- **最难的 bug？** 检索成功不等于答案正确。后续句存在答案时首句摘录错了；共享反例同时验证 Python 和 JavaScript，拒答时保留检索轨迹但无引用。
- **如何测试？** 本轮 49 项 Python、20 项 Node 检查通过；四条旧检索、九条旧可答性案例保留；新增十条摘录案例全部通过。包含真实 CLI/HTTP 子进程测试，不把编译或 HTTP 200 当效果验收。
- **62 条是什么？** 用户已报告审阅全部 62 条，见 [审阅回执](reviews/user-review-receipt-20261021.json)。60 条必需词法案例通过；两个语义改写探针失败，原 expected 未改。没有逐条独立标注决议，来源和期望仍是 synthetic_unverified；旧 pending 字段是历史快照。
- **AI 在哪里？** 可选 SentenceTransformer 做检索；本轮没有运行模型，没有生成模型。旧模式实验不当作本轮验证；生成质量 NOT_RUN，provider 语义 NOT_TESTED。
- **仍缺什么？** 授权真实资料、独立人工标准、语义可答性校准、生产 IAM/部署审查、模型 groundedness 和追踪。既有本地入库和 token 身份不是待开发项。
- **个人贡献与业务结果？** 只描述公开仓库可核查的实现、测试和说明；不推断客户使用、生产准确率、收入或公司项目成果。
